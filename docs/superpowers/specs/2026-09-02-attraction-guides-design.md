# 欧洲文化导览：全景点深度导览设计

## 目标

在现有国庆欧洲旅行网站中增加完整的单景点导览层。导览结构直接参考用户提供的梵蒂冈离线导览站：以真实地点和作品为主体，包含首屏、空间理解、重点作品、现场顺序、实用攻略和离线支持，而不是只提供行程摘要。

网站必须忠实展示现有行程，不调整日期、顺序、票面时间或用户优先级。行程中的同一景点只生成一个完整章节，多条相关行程和票务记录都链接到这个章节。

## 已确认决策

- 覆盖范围采用“全部景点完整导览”，不只覆盖少数重点景点。
- 同一景点只保留一个章节，不按票种、建筑区域或重复日期拆章。
- 梵蒂冈博物馆与圣彼得大教堂直接复用现有离线导览的全部页面、数据和素材，但必须导入当前仓库并从总站子路径打开，不得跳转到旧站或依赖旧站在线。
- 参考梵蒂冈站的信息架构与现场使用方式，不机械复制颜色和布局。
- 现有行程顺序保持不变；导览内容不能反向修改或优化行程。
- 没有行程时不生成路线；本项目存在明确行程，因此景点页可以显示该景点在本次旅行中的已排时间和到达信息。

## 生成前材料审查

### 已有材料

- 腾讯文档详细行程已经整理为 `app/data/trip.ts`。
- 票务、交通和住宿摘要已经整理为 `app/data/bookings.ts`。
- `/Users/dawnkuo/Downloads/tickets/` 中包含票面资料和确认文件。
- 当前站已有城市级图片、旅程总览、城市章节、逐日行程、预订核对和来源页。
- 梵蒂冈参考站的公开仓库和页面可作为交互与离线行为参考。

### 缺失或待补材料

- 当前站只有城市级主图，不足以支持每个景点和作品的独立导览。
- 多数景点尚无经过核验的官方平面图、展厅图、作品清单和图片许可信息。
- 若官方资料没有说明内部结构，不得从旅行博客推测或绘制成精确导航图。
- 行程中标为 `待确认`、`未订` 或“详细时间待补”的项目仍保持原状态，页面不能写成已确认。
- 开放时间、安检、临时关闭和现场规则属于时效信息，发布前必须使用官方一手来源核验并记录日期。

这些问题不阻止页面生成。缺少可靠事实的字段显示 `待确认`，缺少可靠空间资料的景点改用观察点图或地理关系图，不伪造内部路线。

## 景点合并规则

每个导览使用一个稳定的 `guideId`。行程项目通过别名映射到 `guideId`，同一景点的重复项目、不同票种和不同日期都进入同一章节。

明确合并示例：

- `圣彼得大教堂` 与 `圣彼得大教堂穹顶（电梯）` 合并为“圣彼得大教堂”。
- `圣家堂` 与 `受难立面塔与圣家堂补看` 合并为“圣家堂”。
- `米兰大教堂与露台` 作为一个景点。
- `梵蒂冈博物馆 Key Master Tour` 与 `馆内未细看的展厅与藏品` 合并为“梵蒂冈博物馆”。
- `科隆大教堂内部` 与 `科隆大教堂南塔与珍宝馆` 合并为“科隆大教堂”。
- 两天重复出现的 `老桥夜景` 共用“老桥”导览。

不因联票而合并不同景点。例如斗兽场、古罗马广场与帕拉蒂尼山仍是不同景点；比萨奇迹广场中的斜塔、主教座堂、洗礼堂、纪念墓园和博物馆也各自保留章节。

## 信息架构

### 全站入口

主导航增加“景点导览”。入口页按国家、城市和日期展示全部景点，支持类型和预订状态筛选。行程时间轴中的景点标题也直接链接到对应导览。

### 单景点页面

单景点页采用以下固定顺序，结构对应梵蒂冈参考站：

1. **沉浸式首屏**：真实建筑或作品主图、中文名、原文名、城市、当天时间、预订状态和返回当日行程入口。
2. **空间导览**：复杂场馆使用有来源的2D或简化3D空间关系图；广场、桥梁、街区使用注释地图、视线关系或观察点图。
3. **不可错过**：博物馆显示作品；教堂和建筑显示艺术品、空间和构造细节；街区显示建筑节点、历史痕迹和城市视线。
4. **现场顺序**：只基于现有行程、官方单向规则和可靠空间资料组织；不优化跨景点顺序。
5. **实用攻略**：票面时间、入口、安检、行李、摄影、着装、无障碍和离线检查。
6. **来源与核验**：列出官方页面、作品来源、图片许可、编辑判断说明和最后核验日期。

### 现场模式

每个景点页提供“开始现场导览”按钮。现场模式隐藏长篇背景，只保留当前位置、下一观察点、关键作品图、观看提示和返回完整章节按钮。状态仅保存在本机，不要求登录。

## 类型适配

所有景点都拥有完整章节，但模块内容随类型变化：

- **博物馆与美术馆**：展厅关系、必看作品、推荐观看顺序、单向规则和作品详情。
- **教堂、宫殿与纪念建筑**：建筑空间、艺术品、构造细节、上下楼层和观景区域。
- **遗址**：年代分层、地表遗迹、观察点、考古解释和现场方向。
- **广场、桥梁、街区与河岸**：城市空间关系、重要立面、历史节点、最佳观察方向和夜间可见内容。
- **观景台与山丘**：视野方位、可辨认地标、光线方向和上下行方式。

类型适配不会改变页面层级，也不会为不适用的地点硬造馆藏或室内动线。

## 数据模型

新增 `GuideRecord`，核心字段包括：

- `id`、`slug`、`title`、`originalTitle`、`city`、`country`、`kind`
- `embeddedGuide`：导入总站的完整微站路径、按钮文案与素材来源仓库；目前用于梵蒂冈博物馆与圣彼得大教堂
- `aliases`：与行程条目标题匹配
- `scheduledVisits`：日期、时间、状态、票务摘要、到达说明
- `hero`：图片、替代文本、来源、许可
- `overview`、`orientationFacts`
- `spatialGuide`：类型、免责声明、热点和官方图链接
- `highlights`：作品或观察点、作者、年代、位置、观看提示、图片与来源
- `visitSequence`：编号、名称、说明、关联热点
- `practical`：入口、规则、无障碍、现场提醒和待确认项
- `sources`：机构、直达链接、核验结论和日期

行程记录保持现状，只增加可选 `guideId`。同一 `guideId` 对应的所有行程记录在景点页首屏中合并展示。

## 视觉与交互

- 继续使用博物馆编辑式视觉，真实地点和作品占据首屏。
- 参考站中的深色展陈背景、金色辅助信息、编辑式标题和克制动效可保留为设计语言，但每座城市使用少量独立辅助色，避免整站机械复制。
- 3D仅用于空间理解确有价值且资料可靠的复杂场馆；所有3D必须标明为简化示意并提供2D回退。
- 作品列表支持类型筛选和详情展开；简单景点则筛选观察点类别。
- 移动端优先保证现场模式、离线内容和长名称可读，不把核心内容塞进横向卡片墙。
- 不在详情页显示金额。

## 离线策略

- Service Worker 缓存景点索引、全部景点页面、导览数据、必要字体和压缩图片。
- 首次联网加载时显示缓存进度；完成后明确显示“离线已就绪”。
- 外部官方链接标记为需要联网。
- 更新采用新版本缓存，联网优先读取最新页面，断网时回退缓存。
- 不把未经加载的大图宣称为离线可用；发布前进行断网重开测试。

## 错误与不确定性

- 找不到 `guideId` 时显示可返回景点索引的说明页，不出现空白页面。
- 缺少图片时使用城市级真实图片并标注为“城市章节图”，不使用AI伪造建筑照片。
- 缺少空间资料时隐藏3D控制，显示文字和2D观察点。
- 行程与票面冲突时以票面资料为准，并在景点页保留冲突提示。
- 官方未解释关闭或无库存原因时只记录可观察事实，不推测原因。

## 测试与验收

- 数据测试：每个已排景点必须映射到一个有效 `guideId`；同一景点的别名必须映射到同一页面。
- 页面测试：索引筛选、景点页核心区块、现场模式、无结果和待确认状态。
- 构建测试：普通构建与 GitHub Pages 子路径静态导出都必须通过。
- 视觉检查：桌面与移动端验证首屏、空间模块、作品列表和现场模式无重叠或截断。
- 离线检查：缓存完成后断网重载首页、景点索引和至少一个深度页面；内部导航与图片必须可用。
- 来源检查：所有正式图片和时效信息都有机构、链接、许可或核验日期。

## 发布方式

保持现有 GitHub Pages 仓库与自动部署流程。`main` 分支测试和构建通过后自动发布到现有地址，不创建新的站点或改变当前公开链接。
